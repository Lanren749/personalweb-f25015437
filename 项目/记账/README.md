# 月度预算分区记账（阶段6）

> 个人微信小程序项目：预算分区、支出记录、月份明细和超支提醒。当前为开发中的 MVP，详细项目说明见 [PROJECT.md](PROJECT.md)。

个人使用的微信原生小程序 MVP。使用 WXML、WXSS、JavaScript 和微信云开发数据库前端 SDK；没有云函数、npm 依赖、支付或账单自动同步功能。

阶段1至5的功能及阶段6代码修复已写入。2026-10-26 已完成本地语法检查和模拟数据库回归；真实云数据库、微信页面渲染和双账号隔离尚待手动验收。公开源码使用 AppID 与云环境 ID 占位符；运行前请分别配置自己的小程序 AppID 和云环境 ID。

## 新手配置与运行

1. 准备自己的微信小程序 AppID，并使用有该小程序开发权限的微信账号登录微信开发者工具。完整云数据库验收需要可访问所选云环境的真实小程序项目。
2. 打开项目根目录中的 `project.config.json`，核对 `appid` 字段。公开源码使用占位符 YOUR_WECHAT_APPID；换用自己的小程序项目时，将该字段替换为自己的小程序 AppID。不要填云环境 ID。
3. 在微信开发者工具选择“导入项目”，目录选包含 `project.config.json` 的文件夹，确认导入的 AppID 与配置相同。项目无需执行 npm 安装或构建 npm。
4. 打开工具栏的“云开发”，按控制台指引开通并创建环境。进入环境设置，复制环境 ID。环境 ID 与环境名称、小程序 AppID 是不同的值。
5. 打开 `app.js`，核对 `wx.cloud.init` 中的 `env` 与控制台环境 ID 一致。公开源码使用占位符 YOUR_CLOUD_ENV_ID；换用自己的小程序项目时，将 `env` 替换为自己云环境的 ID，保留 `traceUser: true`。不要添加云函数。
6. 在该环境的“数据库”中创建两个集合，名称严格为 `areas` 和 `expenses`。
7. 分别进入 `areas` 和 `expenses` 的权限设置，两个集合都选择并保存“仅创建者可读写”。重新打开设置确认已生效；不要使用公开可读写权限。
8. 点击开发者工具“编译”。从首页进入“区域设置”，新建预算区域，再进入“记一笔”保存第一笔支出。
9. 在数据库控制台核对新记录：金额字段是整数分；`date` 为 YYYY-MM-DD；`month` 为 YYYY-MM；`createdAt`、`updatedAt` 是数值；前端创建记录后由云开发写入 `_openid`。
10. 使用“预览”在有访问权限的微信账号中打开小程序，按下方清单验收。第二个测试账号需要先具备该小程序相应的开发或体验访问权限。

请通过小程序界面创建验收数据，不要在控制台手动伪造 `_openid`。本项目不获取、传入或修改 `_openid`；用户隔离依赖两集合的云端权限。管理控制台能查看数据，不能据此判断小程序用户之间是否隔离。

如提示索引缺失，按控制台或错误详情为对应集合创建索引后重试。本项目批量读取使用 `where({ month })` 并按 `_id` 升序分页；删除区域前检查使用 `where({ month, areaId })`。不要把查询失败当作没有数据。

## 使用规则

- 首页默认实际当前月；上一月、下一月只改变正在查看的月份。进入“区域设置”或“查看本月明细”会带上首页选中的月份；直接打开这些页面时默认实际当前月。
- 区域页为正在显示的月份新增、修改和删除预算。复制按钮将该月份的上一月预算复制进来，以数据库最新区域名称去重；已有同名预算不会被覆盖。复制中断后可重试补齐尚未复制的区域。
- 记账日期始终默认今天。补记其他月份时，先选择对应日期，再选择该月份的区域；如果没有预算区域，返回首页切到该月份进行设置。
- 支出金额必须大于 0，预算可以为 0，最多两位小数。输入元，存储与加总均使用整数分；没有浮点金额累加。
- 剩余 = 预算 − 支出。负数余额标红，并显示“超支 xx 元”。总支出包含当月全部支出，即使某条记录的区域不存在。
- 明细按 `date` 倒序、`createdAt` 倒序；无备注显示“无备注”，区域缺失显示“未知区域”。点击记录编辑，删除需要确认。
- 编辑保留原 `createdAt`，更新 `updatedAt`；`month` 始终由 `date.slice(0, 7)` 生成。跨月编辑必须重新选择目标月区域。
- 首页 `onShow`、下拉刷新会重新查询；从编辑页返回明细也会刷新。网络错误用 toast 提示；区域页、记账页支持点击错误提示重试。
- `fetchAll` 每次 `skip/limit(20)` 分页，读取全部当月数据后再排序、汇总；中途失败会报错，不把部分结果作为完整月份展示。

## 阶段6修复

1. 提高首页余额状态样式的优先级，确保区域负余额不会被普通金额颜色覆盖。
2. 首页到区域与明细保留选中月份；返回原页面仍保留该月份。
3. 复制预算读取目标月最新数据去重，并在确认框出现前锁定操作，防止连续点击重复提交。
4. 删除正在编辑的区域后关闭编辑器；记录消失时保存不会误走新增分支。
5. 区域加载失败与真实空数据分开展示；区域超支文案统一为“超支 xx 元”。
6. 原支出加载失败时锁定编辑保存，重试成功后才可写入；区域加载失败也禁止保存。
7. 记账页卸载后清理返回定时器，慢请求完成不会再执行返回；导航与删除确认失败均给出提示。

下面示例建议使用没有其他数据的月份，金额为测试输入。每项真实验证后再打勾。

- [ ] 配置：真实 AppID、环境 ID 已替换；两集合均存在且权限为“仅创建者可读写”；项目可以编译与预览。
- [ ] 新增与即时刷新：设置“吃饭”100.00 元、“交通”20.00 元、“零预算”0.00 元。新增吃饭支出 12.34 元，返回首页后吃饭剩余为 87.66 元，总剩余为 107.66 元。
- [ ] 编辑与时间字段：从明细将上述支出改为 15.00 元，吃饭剩余为 85.00 元，总剩余为 105.00 元；原 `createdAt` 不变，`updatedAt` 更新。
- [ ] 删除与余额恢复：先取消删除，记录保留；再确认删除，吃饭剩余恢复 100.00 元，总剩余恢复 120.00 元。
- [ ] 月份隔离：切换到另一月只显示那个月的数据；从该月首页进入区域、明细仍是同一月份；跨月修改支出后，原月移除、目标月新增。
- [ ] 零预算与超支：零预算未消费时剩余 0.00 元；向吃饭记录 150.00 元，吃饭剩余为 -50.00 元、总剩余为 -30.00 元，负余额标红并分别显示“超支 50.00 元”“超支 30.00 元”。
- [ ] 账号隔离：账号 A 创建区域与支出；账号 B 打开同一小程序、同一环境、同一月份，看不到 A 的记录。B 创建自己的记录后，A 也看不到 B 的记录。
- [ ] 删除区域保护：吃饭存在支出时删除区域，提示“该区域已有支出，不能删除”；清除该区域支出后再删才成功。
- [ ] 复制预算：在上月创建“吃饭”和“交通”，目标月只创建“吃饭”。复制后仅新增“交通”，目标月原“吃饭”的预算保持不变；再次复制没有新增。
- [ ] 分页：在另一个干净月份设置 100.00 元预算，并录入 45 笔各 1.00 元支出；首页总支出 45.00 元、剩余 55.00 元，明细显示 45 笔。
- [ ] 明细：不同日期倒序，同日期按创建时间倒序；空备注正常。若测试环境中存在区域缺失记录，其区域名显示“未知区域”。
- [ ] 错误恢复：模拟断网后加载区域或编辑记录，出现错误提示；编辑原记录未加载成功前不能保存。恢复网络重试后再保存。
- [ ] 防重复返回：保存慢请求时手动返回，原记账页随后不会再把上一页关闭；返回首页后可下拉刷新核对写入结果。
- [ ] 新手复现：另一位使用者仅按本 README 的配置、运行、验收步骤可以完成首次记账。

## 常见问题

- 初始化或查询失败：先核对 AppID、环境 ID、当前云环境和开发权限，再查看开发者工具控制台错误；不要混用两个项目的环境。
- 没有可选区域：查看记账日期，返回首页切到该日期所属月份设置预算，再重进记账页。
- 数据库权限错误：确认两个集合均已保存“仅创建者可读写”；不要用开放读写权限绕过。
- 写入成功后界面仍旧：返回原页面会触发刷新；网络失败时先恢复网络再刷新，避免盲目重复记账。
