## 2. 真实赛题与本次选题

来源：[CANNJudge · 2026 年 CANN 挑战赛上合赛区初赛 · BatchMatmulMaxSum](https://cannjudge.cn/public/op_challenge_shanghe_prelim/batchmatmulmaxsum)。
该公开页在 2026-10-29 可阅读，页面标注 CANN 9.0.0。

这道题把三个步骤合在一起，用于 query 与 document 的相关性计算：

1. 一一配对的两个 batch 做矩阵乘：`S[b,m,n] = Σk X1[b,m,k] × X2[b,k,n]`。
2. 对每个 query token，在 document token 维取最大相似度：`R[b,m] = max_n S[b,m,n]`。
3. 沿 query token 维求和：`Y[b] = Σm R[b,m]`。

先取最大值再求和，顺序不能交换。全负数的最大值仍然是负数，不能把归约
初始值设为 0。输入按 batch 一一配对，不做 batch 广播。算子不额外做归一化或 mask。

逻辑 shape 固定为 `X1=[B,M,K]`、`X2=[B,K,N]`，输出为 `[B]`。
`transposeX1` / `transposeX2` 描述**存储布局**：

| 属性 | false 时的物理 shape | true 时的物理 shape |
|---|---|---|
| transposeX1 | `[B,M,K]` | `[B,K,M]` |
| transposeX2 | `[B,K,N]` | `[B,N,K]` |

属性不改变数学公式。本项目通过不同索引读取同一逻辑元素；
`store_logical()` 只在准备测试数据时生成相应物理存储。

## 4. 代码思路

- `Tensor`：检查非空三维形状、数据长度、有限数、相同输入类型，使用不可变元组保存数据。
- `quantize()`：先将输入舍入为 FP16 或 BF16 的实际存储值；BF16 使用 nearest-even 舍入。
- `dense_reference()`：显式生成相似度矩阵，用 Python FP64 和 `math.fsum` 做教学参考。
- `tiled_prototype()`：把 M、N、K 分块。每块完成点积后更新行最大值，
  扫描完 N 再累计，避免长期保存完整 M×N 相似度矩阵。
- `float32()`：最终输出舍入到 FP32；Python 返回值仍为 `float`，不是 NPU tensor。

主计算量仍为 `O(B×M×N×K)`。除输入、输出外，分块原型的主要中间存储为
`O(tile_m×tile_n + tile_m)`；这体现“计算完就归约”的思路，**不证明 Python 分块更快**，
也不等于已实现 NPU 上 Cube / Vector 的流水或数据搬运。

本项目输入类型为 FP16 / BF16，**累加使用 Python FP64**，输出舍入为 FP32。
它不是对 NPU FP32 每一步舍入、指令或硬件结果的模拟。正式工程需在真实设备上
按赛题 golden 与官方评测脚本独立验证精度。

## 5. 测试覆盖与边界

13 个测试方法覆盖：官方基础例、官方全负数例、归约顺序、一一 batch 配对、
四种存储布局、两种输入精度、非对齐 M/N 尾块、K 分块尾部、零值、
FP16/BF16 的半值舍入、非法输入、非法分块参数、不修改输入和重复运行一致性。
随机种子固定为 `2505437`。随机部分含 4 组形状 × 2 种精度 × 4 种布局
× 3 组分块参数，共 96 组配置比较。

限制：

- 示例中的 K=2 来自题目说明；随机用例采用 K=8/16/24。
  本教学实现允许任意正维度，不冒充完整的官方维度校验器。
- 未跑官方全部 15 个测试点，未覆盖最大维度、极端数值或官方评分流程。
- 未测 NPU 耗时、吞吐、带宽、加速比或 Cube / Vector 利用率。
- 首次本机测试发现非方阵手算期望误写为 29；逐项验算两行最大值 9 与 21
  后将期望修正为 30。保存的是修正后的实际测试结果。
