## 2. 闭源商业集成的条件判断

**Commons CLI 案例：** 在闭源 Java 商品中使用 Commons CLI，并向客户分发包含该库的程序。Apache-2.0 第2条允许使用、修改和再分发；第4条要求提供许可证副本、对修改文件作显著说明、保留适用声明并妥善处理 NOTICE。满足条件时可闭源商业分发，通常不要求公开自有应用全部源码。第3条还有专利授权与特定诉讼终止条件；第6条并不一般授予商标使用权。不能因为“宽松”就删除许可或归属文件。

**Jekyll 案例：** 复制 Jekyll 的 MIT 代码用于闭源功能。MIT 授权包含使用、修改、再分发、出售等权利，同时要求在副本或软件实质部分保留版权及许可声明。闭源不免除这项义务；依赖、素材、主题与商标仍应分别检查。

**Git 案例：** 复制并改写 Git 的 GPLv2 代码，形成对外分发的派生程序。如果该组合落入 GPLv2 适用范围，第2(b)条要求整体按 GPL 许可，第3条要求履行对应源码提供等义务，仅附一个版权声明不能使方案变成可闭源分发。单纯调用独立 Git 命令与把 Git 源码合入程序的分析不同，须依据实际技术和分发边界判断。GPL 本身不禁止商业收费。

这些是有条件的课程案例分析，不能代替具体产品、版本与分发方式的审查。

## 3. 个人课程项目实际扫描

实际使用 Apache Rat 0.16.1 扫描个人网站的 **四文件子集**：index.html、README.md、LICENSE、THIRD_PARTY_NOTICES.md。精确输入在 evidence/own-site-inputs/，SHA-256 见 own-site-input-sha256.csv。扫描日期为2026-10-29 13:45:53（Asia/Shanghai，证据重跑时间）；后续代码变更不在该快照报告范围内。

| 文件 | Rat 原始分类 | 人工复核 |
|---|---|---|
| index.html | standard；The MIT License；approved=true | 有 MIT SPDX 头；根许可仅覆盖原创程序代码 |
| LICENSE | notice | 应保留 MIT 正文；不能扩展至照片、姓名或报告 |
| README.md | binary | 实际为 UTF-8 中文文本；误分类不能说明无需授权 |
| THIRD_PARTY_NOTICES.md | binary | 实际为 UTF-8 中文文本；须人工阅读授权边界 |

总计4份资源、1 standard、1 notice、2 binary、0 unknown。**0 unknown 不等于完整合规**；两份中文文档未接受等效的文本许可判断。原始 XML/TXT 在 evidence/own-site-rat.xml 与 own-site-rat.txt，未改写检测结果。

components-inventory.csv 是结合扫描与人工核对形成的材料/组件清单，不冒充自动产生的完整 SBOM。页面未观察到外部前端包、CDN 或下载字体；系统字体来自访问者设备。photo.jpg 仅人工盘点，未纳入四文件扫描，且排除于代码 MIT 之外；发布者仍须确认照片来源、版权与肖像使用权。报告文稿与个人信息也不属于代码 MIT 授权。
